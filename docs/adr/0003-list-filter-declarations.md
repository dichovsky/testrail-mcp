# Derive list filter projection and mappings from explicit declarations

Each list filter declares its input schema, driver property, and serialization once; the list module derives runtime projection and production argument mappings from that declaration. Driver bindings remain explicit, and no naming convention infers driver properties. The module owns page/all selection, effective defaults, configured aggregate bounds and reply interpretation. Independently authored parameter fixtures continue to specify expected arguments and requests so they can detect a declaration that is consistently wrong; generated expectations would remove that independent check.
