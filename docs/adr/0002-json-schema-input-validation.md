# Use the published JSON Schema for runtime input validation

Zod remains the authoring and type-inference tool, but the published JSON Schema is the authority for runtime input validation: cloning an adapted Zod schema can lose a parser check while its advertised schema retains the constraint. Registration finalizes an immutable input contract, rejects unsupported schema constructs, and compiles a validator that preserves the caller's original JSON values without coercion, defaults, or field removal. Typed driver bindings share that contract and validate before selecting the driver method. Independently authored parameter fixtures remain the behavioral oracle; agreement between two uses of the same validator is not evidence of correctness. Implemented on 2026-11-17; full checks and the 99% coverage gate passed with all 133 tools' published schemas and metadata unchanged.
