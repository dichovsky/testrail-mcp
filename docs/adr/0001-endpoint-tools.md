# Expose one MCP tool per TestRail API endpoint

The first release requires all 133 baseline TestRail endpoints, so grouping actions into approximately 28 resource tools would produce a smaller visible catalog. We chose an operation-specific tool for every endpoint because each public schema stays focused and read-only, destructive, and idempotent annotations can describe that operation precisely; resource tools could validate equally strictly but would require action-dependent contracts and conservative annotations across all their actions. This accepts a larger catalog, reuses a shared operation registry to control implementation duplication, and treats published tool names as a compatibility contract; actual context cost and client behavior must be measured rather than assumed.
