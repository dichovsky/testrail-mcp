# Own ordinary calls and Attachment transfers in one operation executor

A process-owned operation executor owns invocation and staging lifetimes for ordinary calls and Attachment transfers, exposing execution and idempotent shutdown to transport. This concentrates admission, response abandonment, dispatch observations, driver settlement, and file cleanup without making transport assemble cleanup hooks or making a file-only module shut down a runtime shared by unrelated calls. Existing response, capacity, persistence, and bounded-shutdown contracts remain in force, including the distinction between settlement cleanup of one staged copy and removal of the staging directory after the shutdown drain.

The accepted design is implemented and was locally verified on 2026-11-21. `src/execution/executor.ts` owns the shared driver, runtime and lazy staging area. Transport reuses its `execute(operation, input, options)` and `shutdown()` interface across protocol instances, closes protocol intake before shutdown, and retains signal handling, stdout flushing and process exit. A driver-destruction failure cannot skip staging disposal or reject executor shutdown; disposal receives only the remaining drain budget.
