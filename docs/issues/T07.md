## Outcome

Deliver all 11 assigned TestRail 10.7.0 endpoint tools through the required public driver, enabled by default.

Implement within the accepted local-stdio design: one TestRail identity per process; one tool per endpoint; every operation enabled by default, including writes/admin/delete; no server-added confirmation. TestRail 10.7.0 is the full-coverage baseline; older versions are best effort.

Architecture: [accepted design](https://github.com/dichovsky/testrail-mcp/blob/codex/testrail-mcp-plan/docs/architecture.md). Exact engineering contract: [implementation contracts](https://github.com/dichovsky/testrail-mcp/blob/codex/testrail-mcp-plan/docs/implementation-contracts.md). [Endpoint inventory](https://github.com/dichovsky/testrail-mcp/blob/codex/testrail-mcp-plan/docs/operation-inventory.json).

## Scope

- Implement milestone hierarchy/dates/completion and label CRUD plus bulk deletion, with all supported list filters and paging helpers.
- Test add/update parent null/zero semantics from the selected schemas/API, completion timestamps/booleans, required project IDs, individual label IDs and bulk label containers.
- Keep update/delete/bulk effects explicit and preserve any returned summary; no invented atomicity or cascading workflow calls.

## Acceptance and verification

- [ ] Every assigned operation is registered exactly once with the exact REST token/tool name and public driver binding listed below; no unsupported endpoint, generic dispatcher or helper tool is substituted.
- [ ] Complete the independent F04 parameter manifest and tests for every supported path/query/body/file parameter: requiredness, null/omission, valid unions, filters, supported custom fields and rejection before invocation of invalid input.
- [ ] Each endpoint has deterministic positive and negative contract fixtures invoking the real driver with injected fetch/DNS. Assert the actual HTTP route/query/body or multipart data and the returned wrapper, without deriving expected requests from the registry under test.
- [ ] Cover every applicable page/all helper and important response variants, schema drift, unusable structures, safe errors and mutation outcomes. No silent parameter dropping, field coercion, aggregate truncation, cache workaround or extra upstream workflow call.
- [ ] Registry parity, generated schemas/descriptions, targeted family tests, typecheck and lint pass. Full integration/client/live qualification remains tracked by R01-R03.

Execution order and release gates: [implementation plan](https://github.com/dichovsky/testrail-mcp/blob/codex/testrail-mcp-plan/docs/implementation-plan.md). This issue describes work to implement and verify; it is not a record of completed implementation.
