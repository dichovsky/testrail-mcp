### Resolved — rate-limited report retries are accepted

7.2.0 handles 429 in the rate limiter, above the per-method retry policy, so a rate-limited `reports.runReport` is re-sent; network errors and 5xx are correctly not retried.

Decided 2026-09-17 to accept this and amend the criterion rather than change the driver. TestRail rejects a rate-limited request before handling it, so the re-send cannot generate the report twice or send a duplicate template-configured email, which is the harm the retry ban exists to prevent. A 5xx remains non-retryable because the server may already have begun generating. The original wording was written before it was known which layer handles 429, and was over-broad rather than wrong in intent.

The behavior is asserted by test, so an upstream change to it fails CI and returns here for a fresh decision.
