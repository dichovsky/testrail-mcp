## Outcome

Demonstrate complete 133-operation adapter coverage with independent tests before client and live qualification.

Implement within the accepted local-stdio design: one TestRail identity per process; one tool per endpoint; every operation enabled by default, including writes/admin/delete; no server-added confirmation. TestRail 10.7.0 is the full-coverage baseline; older versions are best effort.

## Scope

- Compare the executable registry and generated catalog with pinned inventory method+route+name+binding identities; fail missing/extra/duplicate mappings or unimplemented parameter manifest entries.
- Run all 133 real-driver fixture contracts plus negative/union cases for every supported parameter. Inspect the serialized request independently of the registry mapping; include custom fields, sentinel/null, UUIDs and bulk shapes.
- Integrate legacy/current packaged stdio tests, output-schema/text parity, all 24 paging helpers, warning isolation, malformed success, unknown writes, caps, soft cancellation, capacity retention after both adapter and driver-internal deadlines, deferred DNS/fetch/body settlement, file containment and persistence.
- Add regression tests for deliberately mutated fixture/registry samples: omitted endpoint, wrong path ID, lost optional query/body parameter, permissive unknown input, duplicate binding and false helper support must fail.
- Publish sanitized machine-readable coverage/parameter reports and fixture evidence as CI artifacts with exact package/driver versions.

## Acceptance and verification

- [ ] All 133 operations, 28 resources, 12 families and 24 page/all bindings are accounted for with independent passing assertions; every parameter-manifest row has coverage, not only every name.
- [ ] CI passes on Node 22/24 across Linux/macOS/Windows; packed executable protocol checks pass for both eras and stdout is clean.
- [ ] Mutation tests prove coverage checks catch meaningful omissions; repeated identical GET drift warnings remain correct under concurrency, and report generation policy tests use the fixed published driver.
- [ ] Reports distinguish offline fixture coverage from live/client results; no real TestRail credentials or user directories are needed for the deterministic suite.
