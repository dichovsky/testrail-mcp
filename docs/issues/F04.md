## Outcome

Define a single typed registration system for exactly133 endpoint tools without losing supported parameters.

Implement within the accepted local-stdio design: one TestRail identity per process; one tool per endpoint; every operation enabled by default, including writes/admin/delete; no server-added confirmation. TestRail 10.7.0 is the full-coverage baseline; older versions are best effort.

Architecture: [accepted design](https://github.com/dichovsky/testrail-mcp/blob/codex/testrail-mcp-plan/docs/architecture.md). ## Scope

- Define registry metadata for route/method/token/name, family, public driver binding, input/outer/advisory schemas, explicit argument map, paging/file capabilities and effects. Family issues populate entries.
- Use top-level REST path names, strict query using REST spelling, body for JSON writes, file_path/optional filename/content_type for multipart, and _mcp only on supported lists. Explicit maps convert driver option names; preserve documented array/scalar serialization.
- Reuse exported Zod payload schemas, supplement runtime constraints and enforce unknown ordinary-field rejection while preserving supported flat custom_* and documented open-object payloads. Preserve omitted versus null and valid sentinel values.
- Create a reviewed independent per-endpoint parameter manifest and fixture format from TestRail/driver sources: requiredness, valid domains/unions, driver argument location, body/query serialization, outer result shape and representative invalid values.
- Generate MCP JSON Schemas, concise descriptions and reference docs. All tools enabled by default; no write unlock or confirmation parameter. Review effects per operation, especially report GETs.

## Acceptance and verification

- [ ] Registry types prevent duplicate tool names and unsupported binding shapes; build-time parity identifies exact missing/extra routes and bindings, not just a total count.
- [ ] Runtime and generated JSON Schema agree on path/query/body/file inputs, including UUID plan entries, numeric/UUID attachment IDs, refs arrays, custom fields, sentinel 0/null and unknown-key rejection.
- [ ] Every parameter in the reviewed manifest has a mapping/validation test requirement; expectations are independent of registry generation. Per-family issues complete all entries before R01.
- [ ] Descriptions are under 2 KiB and annotations describe real effects; no host allow/deny setting is changed and no dispatcher/helper tools enlarge the catalog.
