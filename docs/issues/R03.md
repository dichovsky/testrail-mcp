## Outcome

Release the complete server only when the agreed baseline and required clients have verified behavior.

Implement within the accepted local-stdio design: one TestRail identity per process; one tool per endpoint; every operation enabled by default, including writes/admin/delete; no server-added confirmation. TestRail 10.7.0 is the full-coverage baseline; older versions are best effort.

## Scope

- Prepare a dedicated disposable TestRail 10.7.0 environment/project with the licensed features, permission profiles and fixtures needed for all baseline endpoint families; map each operation to live evidence or a blocking missing capability.
- Run ordered create/read/update/list/close/delete lifecycle checks, bulk operations, BDD/shared steps, datasets/variables, plan configurations, metadata/admin, attachments and report generation. Use report templates configured for the test to control notification effects.
- Record API/license/permission/version limitations without hiding tools; older versions are best effort. Live evidence must distinguish supported baseline failure from unavailable test infrastructure.
- Qualify exact fixed published driver from F01, rerun deterministic/client gates for the final candidate, and produce package/version/lockfile/integrity/SBOM or dependency inventory, changelog and endpoint reference.
- Create a version-tagged GitHub Actions release workflow using npm trusted publishing where available, protected release environment and least-required token permissions. Publish only after the actual release is authorized under repository policy, then verify install and packaged stdio startup from the exact registry artifact.
- Document upgrade/rollback via exact npm versions and compatibility policy; do not delete previously downloaded attachments during upgrade or uninstall.

## Acceptance and verification

- [ ] Every baseline operation has passing deterministic contracts and the required live qualification evidence; missing licensed features/infrastructure remain blocking rather than being counted as passes.
- [ ] All required client records pass for the final candidate and the published driver includes network-guard and report-generation fixes plus the public operation-settlement API. All 133 tools are enabled with full supported parameter coverage.
- [ ] The release artifact installs and runs from npm on certified platforms with no credentials bundled; tag, changelog, dependency provenance and integrity match the tested build.
- [ ] README/configuration/reference docs match shipped names, budgets, side-effect annotations, files, errors and pagination limits. Publishing credentials are never stored in source or evidence.
